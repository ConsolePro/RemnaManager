# Маршрутизация Xray и WARP Native

## РФ напрямую, остальное через выбранные ноды

1. Откройте «Маршрутизация Xray и WARP → Настроить маршрутизацию: РФ напрямую».
2. Выберите **существующий клиентский шаблон XRAY_JSON**, например Default.
3. Отметьте нужные ноды пробелом и нажмите Enter.
4. Проверьте краткое описание и подтвердите применение.
5. Обновите подписку XRAY_JSON в клиенте.

Названия схем и группы не запрашиваются. Новый шаблон, профиль ноды, хост
или сквад не создаётся. Меняется JSON выбранного существующего шаблона,
его имя и назначения сохраняются. Изменение распространяется на всех
получателей этого шаблона; это указывается перед применением.

Домены `.ru`, `.su`, `.рф`, категория `geosite:category-ru` и `geoip:ru`
направляются напрямую. Остальной TCP/UDP — через хосты выбранных нод.
Хосты определяются по UUID ноды, а при отсутствии ограничения nodes —
по её конфигурационному профилю. При нескольких подключениях используется
leastPing/observatory; при недоступности группы трафик блокируется,
автоматического перехода на прямое соединение нет.

Клиенту нужны GeoIP/GeoSite с указанными категориями. Обычная VLESS-ссылка
не передаёт эти правила. Наличие баз на сервере ноды не заменяет базы
на устройстве пользователя. Требуется Remnawave с injectHosts (2.6.3+).
Все выбранные подключения должны быть доступны пользователю через его сквады.
Состав сквадов менеджер не меняет.

Исходный JSON и этап операции сохраняются в `/var/lib/remnamanager/quick-routing`
с правами 0600. Потеря ответа API не приводит к повторной записи уже сохранённой
конфигурации. Если шаблон изменился между просмотром и подтверждением,
применение остановится, сохранив ручные изменения. Повторная настройка
не добавляет новые уровни инжекта поверх прежней управляемой конфигурации.
Шаблон с посторонним injectHosts автоматически не переписывается.

## Установка WARP Native

«Маршрутизация Xray и WARP → Установить WARP Native на ноду» → выберите ноду →
подтвердите установку. Подключение использует сохранённый SSH-ключ. Если
потребуется восстановление SSH, используется обычный парольный сценарий ноды.
Путь к WireGuard-профилю вводить не нужно.

Менеджер устанавливает wireguard-tools, получает официальный бинарник wgcf
с проверкой SHA256, регистрирует аккаунт Cloudflare и поднимает интерфейс
`rmwarp`. Перед подтверждением указаны условия WARP, которые принимаются
при регистрации аккаунта. Готовый аккаунт используется повторно.
Файлы, ключи, конфигурация и приватный журнал: `/opt/remnanode/warp`.
Systemd-службы ссылаются на этот каталог. DNS системы не перезаписывается.

Используется IPv4-выход WARP. Таблица 51888 обслуживает только помеченные
соединения и источник интерфейса; основной маршрут сервера и SSH сохраняются.
Правила имеют приоритеты 10000/10001, до системного main с приоритетом 32766.
При повторной установке старые управляемые правила 51888/51889 заменяются
автоматически, а аккаунт сохраняется. Перед проверкой Cloudflare установщик
проверяет фактический маршрут для источника WARP и метки: оба должны вести
через rmwarp. При недоступности UDP 2408 пробуются официальные резервные
порты 500, 1701 и 4500 на том же адресе Cloudflare; рабочий endpoint сохраняется.
`rm-native-warp` привязан к `rmwarp` и mark 51888. Nftables блокирует выход
помеченного трафика через другой интерфейс. Добавленные NET_ADMIN/NET_RAW
сохраняются при обновлении контейнера ноды.

После проверки Cloudflare trace (`warp=on` или `warp=plus`) менеджер добавляет
выход и правило в **существующий серверный профиль Xray ноды**. Это серверная
часть, как в примере eGames. Клиентский шаблон не может привязать свой сокет
к сетевому интерфейсу удалённого сервера. Секретный ключ WARP в подписки
пользователей не попадает.

Начальный список сайтов совпадает с примером: whoer.net, browserleaks.com,
2ip.io и 2ip.ru. Остальной трафик использует прежние правила. Список можно
изменить в правиле `outboundTag: rm-native-warp` серверного профиля в панели.
Клиентская схема «РФ напрямую» настраивается отдельно описанным выше коротким
сценарием и не заменяет серверный WARP.

Перед записью профиля Xray на ноде выполняет `run -test`. После записи
запрашивается перезапуск, а появление нового процесса Xray и подключение
к панели проверяются автоматически. При ошибке сетевой проверки или
предварительной проверки Xray профиль не применяется. Установленные файлы
и аккаунт сохраняются для повторной попытки или удаления.

Поддерживаются завершённые ноды, установленные менеджером. При незавершённом
обновлении, firewall или восстановлении сначала завершите ту операцию.
Если серверный профиль используется несколькими нодами, установка на одну
ноду откажет до изменений: нужен её отдельный профиль. Создавать его
или менять назначения других нод автоматически менеджер не будет.

## Удаление WARP

«Маршрутизация Xray и WARP → Удалить WARP Native с ноды» → выберите ноду →
подтвердите. Сначала из серверного профиля удаляются управляемый выход
и его маршруты, затем проверяется перезапуск Xray и выключается интерфейс.
Посторонние правила, DNS и настройки Compose сохраняются. Аккаунт и копии
остаются в `/opt/remnanode/warp` для повторной установки.

Операцию можно повторить после потери API/SSH. Чужая установка WARP,
занятые сетевые правила, вручную изменённый управляемый outbound или
новые изменения профиля во время удаления блокируют автоматическую перезапись.

Начиная с 1.5.2 проверка ядра определяет настоящий исполняемый файл процесса,
включая запуск через `rw-core`, и учитывает идентификатор контейнера.
Установка после прерванного удаления сама завершает очистку перед новой
установкой. Если профиль при неудачной установке вообще не менялся,
удаление не требует лишнего перезапуска Xray. Завершённая очистка сохраняется
как удаление даже при последующей ошибке проверки здоровья ноды.

## Старые схемы 1.4.0

Пункт «Ранее созданные схемы» позволяет продолжить или удалить ранее созданный
отдельный шаблон. Новый короткий сценарий такими схемами не пользуется.

## Проверки и источники

Go-тесты проверяют изменение существующего шаблона без создания ресурсов,
повторное применение, потерю ответа API, конфликты ручных правок и короткую
навигацию. Изолированный `tests/node-warp-fixture.py` проверяет установку,
повторный запуск, отказ trace, проверку перезапуска и удаление агента;
системные команды и сетевой ответ в нём подменены. Конфигурации клиента
и серверного WARP дополнительно проверяются официальным Xray v26.11.9.
Это не проверка живого туннеля конкретной ноды: её установщик выполняет отдельно.
