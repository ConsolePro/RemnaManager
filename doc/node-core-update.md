# Отдельное обновление Xray

«Ноды и расширения → Управление нодой → Обновить ядро Xray» обновляет Xray из последнего стабильного релиза `XTLS/Xray-core`, сохраняя digest образа Remnawave Node. Нужна завершённая Go-установка версии 2 или новее, включённая и подключённая нода.

Первичная установка ноды использует только ядро, встроенное в официальный образ Remnawave Node. Отдельное скачивание или обновление Xray при установке не выполняется.

После выбора ноды менеджер читает текущую `xrayVersion` из свежего ответа панели и сравнивает её с последним стабильным релизом [XTLS/Xray-core](https://github.com/XTLS/Xray-core/releases). Обновление предлагается только если установленная версия ниже. При равной или более высокой версии выводится «Версия ядра Xray актуальная», без SSH, скачивания архива и перезапуска контейнера. Если текущая версия неизвестна, операция останавливается.

Перед подтверждением показываются текущая и выбранная версии. Непосредственно перед выполнением текущая версия проверяется повторно: если она уже обновилась, повторной установки не будет. Используется сохранённое SSH-подключение; при необходимости менеджер восстанавливает клиентский ключ через пароль root. Ручной ввод отпечатка не требуется.

## Ручной откат на более раннюю версию

Выберите «Ноды и расширения → Управление нодой → Откатить ядро Xray», затем ноду. Менеджер получает до 100 последних релизов из официального репозитория XTLS/Xray-core, исключает draft/prerelease и показывает стабильные версии ниже текущей, от новых к старым. Выберите версию стрелками и подтвердите установку. Откат доступен и для ядра из исходного образа, даже если менеджер ещё ни разу не обновлял его.

Выбранный релиз повторно проверяется в GitHub перед загрузкой. Откат использует ту же проверку SHA256, версии, работающего процесса и подключения к панели, что и обновление. При неудаче восстанавливается Compose с предыдущим ядром. Установка равной или более высокой версии через пункт отката запрещена.

Менеджер выбирает официальный архив для amd64/arm64, получает SHA256 из GitHub Assets либо официального `.dgst` и передаёт закреплённые URL и контрольную сумму на ноду. Архив скачивается по HTTPS, проверяется и извлекается только исполняемый файл Xray. Проверяются ELF-сигнатура и запуск выбранной версии внутри существующего контейнера.

Ядро хранится в `/opt/remnanode/xray/vX.Y.Z/amd64/xray` либо `arm64/xray` и подключается read-only к `/usr/local/bin/xray`. Такой способ соответствует штатному пути bundled core: [CoreLoaderService Remnawave](https://github.com/remnawave/node/blob/main/src/modules/xray-core/core-loader.service.ts). Если панель уже управляет другим ядром через `geodata.core`, менеджер отказывает в замене, чтобы не конкурировать с этим механизмом.

Меняется только bind mount ядра в Compose. Остальные volumes, environment, ключи, образ ноды и профиль сохраняются. Обновление самого контейнера в дальнейшем сохраняет этот mount; установленная версия ядра не заменяется незаметно вместе с образом.

## Проверка и откат

Перед пересозданием контейнера сохраняется полный прежний Compose, запускается независимый таймер отката на 300 секунд и устанавливается systemd-сервис восстановления после перезагрузки. Затем проверяются:

- подключение к панели с выбранной `xrayVersion`;
- публичный HTTPS сайта и перенаправление HTTP→HTTPS;
- вывод версии внутри контейнера и SHA256 реально работающего процесса Xray.

Только после этих проверок новая версия сохраняется в журнале. Неуспешная проверка запускает откат через отдельный SSH-контекст; если SSH недоступен, остаётся удалённый таймер. Потерянный ответ после commit распознаётся по удалённому журналу и не отменяет успешно установленное ядро.

Для восстановления прерванного обновления повторно выберите тот же пункт. Сначала будет завершено только восстановление, без нового обновления. Пока транзакция Xray не завершена, смена сайта и обновление контейнера блокируются. Прежние бинарники и Compose сохраняются в `/opt/remnanode/state/core-updates/`.

Обновление перезапускает контейнер и может прервать клиентские соединения. Совместимость клиентов с изменениями конкретной версии следует проверять по release notes Xray: проверка связи с панелью и HTTPS не заменяет проверку всех клиентских приложений.

## Проверки

`go test ./...` проверяет успешную установку, отказ apply, отмену, потерянный ответ commit, сохранение образа и ключей и восстановление mount после повторного чтения журнала.

`python tests/node-core-fixture.py --bash /path/to/bash --jq /path/to/jq` выполняет настоящий shell-код транзакции в отдельном временном каталоге: prepare/apply/commit, возврат Compose, отказ по неправильной контрольной сумме и версии. Docker, systemd и загрузка архива заменены тестовыми командами; полноценная проверка на живой ноде выполняется отдельно.
