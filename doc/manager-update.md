# Обновление менеджера

Раздел «Версии и обновления» поддерживает установку последнего стабильного релиза, выбор конкретного `vX.Y.Z` и локальный откат. Обновляется только `/usr/local/lib/remnamanager/remanager`: конфигурация менеджера, база данных, сертификаты, панель и ноды не переустанавливаются.

Механизм доступен установленному Go-менеджеру на Linux от root. В деморежиме и при запуске произвольного бинарника из исходников замена отключена.

## Порядок

1. Выберите обновление, конкретную версию либо откат. На экране подтверждения показаны текущая и выбранная версии и SHA256.
2. После подтверждения менеджер повторно проверит метаданные релиза, загрузит бинарник и сверит SHA256. Поддерживаются Linux amd64/arm64. Проверяются ELF-архитектура, Go module identity и точное совпадение вывода `--version` с выбранным тегом.
3. Прежний бинарник и его метаданные сохраняются рядом в `remanager.previous` и `remanager.previous.json`. Новый файл устанавливается атомарным переименованием.
4. Проверка запуска повторяется после замены. При неудаче возвращается прежний файл. Журнал `remanager.update.json` позволяет завершить восстановление прерванной операции; посторонние изменения бинарника не перезаписываются.
5. На итоговом экране нажмите Enter: TUI закроется, SSH control-сессии освободятся, терминал восстановится и запустится новая версия с прежними аргументами, включая `--config`.

Откат использует локальную проверенную копию и не требует доступа к GitHub. Два обновления одновременно блокируются файловой блокировкой. Пакеты и удалённые shell-скрипты во время самообновления не исполняются.

Проверка запуска означает успешное выполнение `--version`, а не полную проверку всех функций новой версии. Предыдущая копия остаётся доступна для ручного отката через меню.

## Файлы релиза

В `ConsolePro/RemnaManager` релиз должен содержать:

- `remanager-linux-amd64`;
- `remanager-linux-arm64`;
- `checksums.txt` с SHA256 файлов.
- `install.sh` — установщик готового бинарника без Go SDK на сервере.

При наличии SHA256 в метаданных GitHub Assets используется он; иначе читается `checksums.txt`. Релизы без Go-бинарника, включая прежние Bash-дистрибутивы, не устанавливаются этим механизмом. Draft и prerelease исключены.

Workflow `.github/workflows/release.yml` запускается при push тега `vX.Y.Z`, выполняет тесты, собирает статические бинарники с версией в `updater.Version`, создаёт контрольные суммы и прикрепляет файлы к draft-релизу. Создание workflow само по себе ничего не публикует. Для обновлений через меню draft нужно опубликовать отдельно.

Первая установка запускает скрипт из репозитория: `curl -fsSL https://raw.githubusercontent.com/ConsolePro/RemnaManager/main/install.sh | sudo bash`. Скрипт определяет ОС, архитектуру и актуальный стабильный релиз, затем скачивает подходящий бинарник из Releases. Флаг `--version vX.Y.Z` закрепляет выбранный релиз. Сборка из исходников остаётся только для явных `--source`/`--ref`; для распознавания прежнего Go-менеджера используется встроенная проверка метаданных `--inspect-manager`, а не системный Go.
