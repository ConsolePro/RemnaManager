# Установка ноды через SSH

«Ноды и расширения → Добавить ноду» устанавливает Remnawave Node на отдельный VPS и создаёт профиль VLESS Reality, объект ноды, хост подписки и internal squad. Для доступа пользователей назначьте им созданный squad.

## Требования

- Панель этой Go-версии с действующим API-токеном, завершённой установкой и подтверждённым SSH-доступом.
- Отдельный чистый VPS: Debian 12/13 или Ubuntu 22.04/24.04, amd64/arm64, systemd и root SSH.
- IP или домен SSH-сервера. Если используется домен, DNS должен вести на этот VPS.
- Собственный домен сайта selfsteal с A/AAAA на тот же VPS, без CDN-проксирования. Все A/AAAA-записи должны вести на ноду. Домен панели или подписки не подходит. IDN — в punycode.
- Email в настройках менеджера, исходящий HTTPS, TCP 80/443 и доступность порта API с IP панели.

Активные UFW/firewalld, чужие INPUT-правила, существующая панель, чужая конфигурация прокси или занятые порты требуют предварительной миграции. Чужие сервисы автоматически не останавливаются.

## Мастер для новой установки

1. **Подключение.** Введите IP/домен и SSH-порт сервера. Пользователь — root. Путь к своему SSH-ключу необязателен; оставьте его пустым для входа по паролю.
2. **Идентификация сервера.** Менеджер покажет SHA256-отпечаток SSH-сервера. Это не ваш приватный ключ и не ключ от панели хостинга.
   - Если уже есть доверенное SSH-подключение к ноде, выполните там команду ниже и сравните SHA256. Подходит и консоль провайдера.
   - Если независимой проверки сейчас нет, Tab переключает на «Первое подключение: довериться показанному ключу». Enter сохраняет доверие этому ключу. Это не подтверждает владельца сервера независимым способом.
   - Если сохранённый ключ изменился, первое доверие недоступно: нужен проверенный отпечаток. При возобновлении установки неизменившийся ключ не требуется вводить повторно.

        ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub

3. **Пароль и собственный ключ.** OpenSSH запросит пароль root со скрытым вводом. Пароль не передаётся в аргументах процесса и не сохраняется менеджером. После входа создаётся отдельный Ed25519-ключ, его публичная часть добавляется к существующим authorized_keys. Менеджер проверяет новое соединение только по этому ключу, без старой control-сессии, и лишь затем сохраняет путь к ключу.
4. **Параметры после подключения.** Укажите название ноды, страну, название профиля, порт API (по умолчанию 2222), домен selfsteal и шаблон сайта. Страна выбирается с поиском по русскому/английскому имени или коду; список соответствует интерфейсу панели. Для профиля допустимы 2–30 латинских букв, цифр, пробелов, дефисов и подчёркиваний.
5. **IP панели.** Можно оставить пустым: он определяется по SSH с учётом NAT и предлагается для подтверждения. Нужен адрес, с которого backend подключается к API ноды; при разных маршрутах SSH и backend его следует исправить.
6. **Подтверждение установки.** Проверьте параметры. До этого шага на ноде настраивается только SSH-ключ; пакеты, proxy и firewall ещё не меняются.
7. **Развёртывание.** Проверяется сервер, создаются профиль и объект ноды в API, устанавливаются зависимости, получается SECRET_KEY и закрепляется образ по digest. Затем устанавливаются сайт и сертификат, запускается Remnawave Node. После запуска создаются хост с fingerprint firefox и squad. Проверяются связь с панелью, публичный HTTPS с действительным сертификатом и перенаправление HTTP→HTTPS.
8. **Firewall.** После применения правил откройте второе SSH-подключение к ноде. Нажмите Enter в течение 120 секунд для сохранения правил. Без подтверждения отдельный таймер выполнит откат.

SSH по ключу используется для установки и управления. Постоянный туннель для API не создаётся: API доступен напрямую только с подтверждённого IP панели и использует штатную защиту Remnawave.

## Профиль Reality и подготовленные сайты

За основу взят [официальный VLESS selfsteal с Nginx](https://github.com/remnawave/templates/blob/main/by-unknown/xray-core/example-vless-selfsteal-with-nginx.json). Профиль хранится в internal/installer/node_assets/reality.json; подставляются только данные ноды:

- tag VLESS_REALITY_<название профиля>, пробелы заменяются подчёркиваниями;
- новый X25519 privateKey и 3–6 независимых shortIds по 8 байт;
- serverNames из собственного домена, target 127.0.0.1:8443;
- RAW/Reality, PROXY protocol v1 (xver: 1), стандартные блокировки private-адресов/доменов и BitTorrent.

Ключи и shortIds сохраняются до создания профиля. Повтор не меняет их и не создаёт дубликаты объектов. Профиль с чужой конфигурацией не перезаписывается; занятость имени проверяется до запуска установки.

Заранее подготовлены Northline Studio, Field Atlas и Common Table: главная, разделы, стили, favicon и страница 404. Можно выбрать сайт или случайный из этих трёх. Выбор сохраняется в журнале; сайт на сервере не генерируется.

Внешний TCP 443 занимает Xray. Обычный HTTPS без Reality-аутентификации передаётся в настоящий Nginx с сертификатом и файлами сайта. HTTP на 80 перенаправляет на HTTPS, кроме пути ACME. Проверка на настоящих Xray/Nginx подтверждает работоспособность этой схемы, но не гарантирует необнаружимость средствами ТСПУ.

## ACME и обновление сертификата

Новые установки используют acme.sh 3.1.6 с закреплённым коммитом 807da6498377ee5e0cf43a78091f46f12dc59a89 и SHA256:

    c7d68b021cfd6380ea83a82962abde5b484779fee0b97d38681dfa1396bbc8d7

SHA256 рассчитан по точным байтам исходного HTTPS-файла с LF, а не по Windows-checkout с CRLF. Код проверяется до запуска; автоматическое обновление самого клиента не включается. Выпуск — Let's Encrypt, HTTP-01 webroot на /.well-known/acme-challenge/, ключ сертификата EC-256.

- /var/lib/remnamanager-node/acme/ — клиент, аккаунт и данные выпуска.
- /var/lib/remnamanager-node/ssl/fullchain.pem и privkey.pem — рабочий сертификат Nginx.
- remnamanager-node-acme.timer — ежедневная проверка продления с отложенным стартом.
- reload-hook выполняет nginx -t и systemctl reload nginx.

TCP 80 остаётся открыт, поэтому продление не требует останавливать контейнер ноды или Nginx. После успешной замены файлов Nginx перечитывает сертификат.

Логика сверена с [Remnanode-manager](https://github.com/ConsolePro/Remnanode-manager/tree/11532a46c9d0cbe9cd1f3ffbbf57dfd2aa350ef8). Список стран взят из [официального интерфейса Remnawave](https://github.com/remnawave/frontend/blob/4bf4b813d83de55d49cea754f2f0ee7b3f5fd1c7/src/shared/ui/forms/nodes/base-node-form/constants/countries.ts).

## Firewall

Ограничение API по IP панели действует до запуска контейнера. Полная политика закрывает остальные новые входящие подключения.

| Назначение | Доступ |
| --- | --- |
| SSH | 22 и порты из эффективной конфигурации sshd/SSH-сессии |
| TCP 80 | HTTP→HTTPS и ACME HTTP-01 |
| TCP 443 | Reality и обычный HTTPS сайта |
| API, по умолчанию TCP 2222 | Только подтверждённый IP панели; loopback разрешён |
| TCP 8443 | Только loopback для target Reality |
| Остальные новые входящие | Закрыты |

API-порт настраивается, но не может совпадать с SSH, 22, 80, 443 или 8443. Правила IPv4/IPv6 находятся в собственной таблице inet remnamanager_node. Сохраняются established/related, loopback, ICMP и DHCP. Входящий транзит закрыт, включая Docker-публикации; исходящий трафик Docker разрешён. Глобальный ruleset и firewall провайдера не очищаются.

## Продолжение и секреты

Подключение сохраняется до входа root. При выходе на этапе параметров оно доступно в «Незавершённых установках». При ошибке DNS или занятости имени форма сохраняет введённые значения. При последующем сбое возобновляется тот же журнал с теми же ключами и UUID.

Приватный SSH-ключ находится на сервере панели: /var/lib/remnamanager/ssh/keys/node-<ID установки>, права 0600, каталог 0700. Сохраните каталог ssh в защищённой копии; штатная копия БД включает журналы нод, но не эти ключи. Пароль root и существующие ключи не меняются; вход по паролю автоматически не отключается.

Новые журналы имеют версию 2 с новым порядком этапов. Журналы версии 1 продолжаются в прежнем порядке с их профилем, ключами и certbot; работающая нода автоматически не переписывается. Потерянный журнал нужно восстанавливать из копии, а не заменять новыми ключами. См. также [обновление](node-update.md) и [переустановку](node-reinstall.md).

## Проверки

- go test ./... — мастер, русский/английский вывод, первое доверие и запрет обхода проверки изменённого ключа, страны, сайты, порты, обе версии журнала, восстановление API после потери ответа.
- TestLiveRootPasswordToManagedKey — настоящий OpenSSH в отдельном контейнере: неправильный/верный пароль, установка и повтор ключа, новое подключение после закрытия исходной сессии.
- TestLiveNodeV2APIAndRealityWebsite — настоящие backend 3.4.9, remnawave/node и Nginx: профиль до регистрации/запуска ноды, shortIds, DE, API 3333, Firefox-хост, подписка с Vision/Firefox и правильными ключами, HTTPS через Reality к страницам сайта.
- TestNodeV2AgentWebsiteRenewalAndCustomPort — настоящие Nginx/TLS/nftables, PROXY protocol, HTTP→HTTPS, ресурсы сайта, замена сертификата, таймер и API 3333. ACME, Docker и systemd здесь заменены управляемыми тестовыми командами; публичный выпуск Let's Encrypt не выполняется.
- TestRealACMENodeIssueRenewAndResume — настоящий acme.sh с локальным ACME-сервером Pebble: отказ для CRLF-копии по SHA256, повтор с оригинальными LF-байтами без очистки установки, регистрация аккаунта, настоящий HTTP-01 через Nginx, выпуск и установка сертификата, cron-проверка, принудительное продление, reload и повторное развёртывание. TLS проверяется по тестовым CA без отключения проверки сертификата. Подменены только Docker/systemd и адрес CA; публичный Let's Encrypt не используется.
- TestNodeAgentStagesInDisposableContainer — прежний порядок этапов, firewall-откат и продолжение старой установки.

Интеграционные проверки запускаются только в выделенных временных контейнерах. Порты панели и сайта публикуются лишь на 127.0.0.1.

При ошибке удалённый агент передаёт безопасный код операции: проверка SHA256, регистрация ACME, выпуск/установка сертификата, Nginx, firewall или запуск контейнера. Интерфейс показывает конкретную причину на выбранном языке и путь к журналу, без приватных ключей и токенов.
