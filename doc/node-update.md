# Обновление установленной ноды

Пункт «Ноды и расширения → Управление нодой → Обновить ноду» обновляет контейнер ноды на отдельном VPS через SSH. Поддерживаются завершённые установки этой Go-версии с сохранённым журналом `node-jobs/ID.json`. Для нод, добавленных вручную или старой Bash-версией, сначала требуется отдельная миграция; автоматического импорта пока нет.

## Порядок работы

1. Выберите ноду из списка панели. Перед новым обновлением она должна быть включена и подключена.
2. Сверьте и введите SHA256-отпечаток SSH-ключа. На экране подтверждения показан текущий закреплённый образ. Программа повторно проверяет ключ перед аутентификацией через OpenSSH.
3. Подтвердите обновление. Контейнер будет перезапущен; активные клиентские соединения могут оборваться.
4. Программа загрузит официальный `remnawave/node:latest`, сохранит полученный digest, создаст закрытую копию Compose и заменит только поле образа сервиса `remnanode`.
5. После запуска проверяются состояние контейнера, соответствие запущенного Docker image ID ожидаемому образу и доступность ноды в API панели. Затем новый образ закрепляется в журнале установки.

Ключ ноды, Reality private key и short ID, профиль, inbound, хост подписки, squad, Nginx, сертификаты и firewall не пересоздаются. Конфигурация Compose сохраняется; обновление меняет только образ. Если полученный digest совпадает с текущим, контейнер не перезапускается.

## Ошибки, отмена и восстановление

Перед заменой Compose на ноде включаются независимый 300-секундный таймер отката и постоянный systemd-сервис восстановления после перезагрузки. При ошибке запуска или проверки программа пытается вернуть прежний Compose и запустить старый образ через отдельную SSH-операцию, не отменяемую вместе с экраном TUI.

Если SSH недоступен, таймер выполнит ту же попытку на ноде. После перезагрузки восстановление запускается после Docker. Старый образ не удаляется. Успешное подтверждение записывается атомарно; поздний таймер проверяет этот маркер и не отменяет завершённое обновление.

Если операция прервалась, повторно выберите «Обновить ноду». При наличии незавершённой транзакции этот запуск **сначала выполнит только восстановление**: вернёт старый контейнер либо распознает уже подтверждённый новый образ. Для нового обновления после восстановления выберите пункт ещё раз. Если прежняя нода пока не подключается к панели, журнал восстановления остаётся до устранения проблемы.

[Переустановка контейнера](node-reinstall.md) использует тот же механизм с сохранением прежнего digest и принудительным пересозданием. Незавершённую транзакцию можно восстановить через любой из двух пунктов; сохранённый режим операции при этом не меняется.

Не удаляйте каталоги состояния во время восстановления:

- На сервере панели: `/var/lib/remnamanager/node-jobs/ID.json`. Поля `UpdateID` и `UpdateTarget` сохраняют незавершённую транзакцию; этот файл входит в резервную копию панели.
- На сервере ноды: `/var/lib/remnamanager-node/updates/UPDATE_ID/`, права каталога 0700. Здесь находятся прежний и новый Compose, digest, состояние транзакции и скрипт отката. Файлы имеют права 0600 и могут содержать секреты.
- Диагностика на ноде: `/var/lib/remnamanager-node/install.log`. systemd-сервис: `remnamanager-node-update-rollback.service`; таймер проверки: `remnamanager-node-update-rollback-trial.timer`.

После успешного обновления закрытые копии сохраняются для диагностики и не очищаются автоматически. Ручная смена образа в Compose или адреса ноды в панели вызывает отказ вместо перезаписи состояния. Если метаданные подготовленного обновления пропали, программа сохраняет журнал и требует проверки состояния.

## Проверки

Модульные тесты проверяют успешное обновление, совпадение digest, ошибку запуска, потерю SSH, потерю ответа после commit, сохранение ключей и отказ от изменения чужой/незавершённой установки. Тест интерфейса проверяет выбор ноды, сверку SSH-ключа и отдельное подтверждение перед запуском.

Контейнерная проверка `TestNodeAgentStagesInDisposableContainer` также выполняет настоящий Bash-скрипт обновления с тестовыми Docker/systemd-командами: замена образа, точное восстановление прежнего Compose, независимый скрипт отката и запрет позднего отката после commit. Это не сквозная проверка обновления настоящего контейнера Remnawave Node с реальным systemd и перезагрузкой VPS.

Исходный компонент: [официальный репозиторий Remnawave Node](https://github.com/remnawave/node). Повторение изолированных тестов описано в [инструкции установки ноды](node-installation.md).
