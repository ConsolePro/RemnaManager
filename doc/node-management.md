# Управление существующими нодами

Этот этап переносит управление нодами, уже зарегистрированными в панели. Раздел работает через сохранённый API-токен Go-установки. В `--demo` реальные запросы отключены.

## Работающие пункты

| Пункт | Поведение |
| --- | --- |
| Список нод | Получает настоящий список из API, сортирует по имени, показывает адрес и состояние. ↑/↓ — выбор, Enter — подробности, R — обновление. |
| Переименовать | Выбор ноды, новое имя из 3–30 символов, подтверждение с UUID, PATCH выбранного объекта. |
| Включить / отключить в панели | Отправляет явное enable/disable. Повторное подтверждение того же состояния не инвертирует его обратно. |
| Перезапустить Xray | Для включённой и подключённой ноды отправляет API-запрос принудительного перезапуска Xray. Успешный ответ означает принятие запроса; итог проверяется в статусе. |
| Статус ноды | Адрес, API-порт, состояние и доступные версии, аптайм, время изменения статуса и сообщение, возвращённые панелью. |
| SSH-подключение | Настройки SSH, сверка Ed25519 host key по SHA256, подтверждение и интерактивный OpenSSH от root. После выхода интерфейс восстанавливается. |

Изменение состояния в панели не останавливает контейнер и не гарантирует прекращение трафика на удалённом сервере. Поэтому пункт назван «Включить / отключить в панели». Статус показывает сведения API; удалённые Docker-логи на этом этапе не заявлены.

Добавление ноды и возобновление прерванной установки реализованы в [мастере установки](node-installation.md). Он устанавливает Nginx selfsteal, создаёт Reality-профиль и подключает ноду к панели. [Обновление контейнера](node-update.md) доступно для нод, установленных Go-версией: с сохранением конфигурации и откатом при ошибке. Отдельная смена selfsteal, обновление Xray и переустановка остаются явно помеченными «В разработке».

## SSH

Укажите IP или полный DNS-домен, SSH-порт и при необходимости абсолютный путь к приватному ключу на управляющем сервере. Пустой путь оставляет аутентификацию стандартным ключам, локальному SSH agent или паролю, который запросит сам OpenSSH. Приложение не читает содержимое приватного ключа и не сохраняет пароль.

Перед подключением программа получает публичный Ed25519 host key и показывает его полный SHA256-отпечаток. Сверьте его через консоль хостинга и введите полностью. Если ключ, адрес или порт изменились относительно сохранённых настроек, показывается отдельное предупреждение. Перед сохранением ключ сканируется ещё раз: если сервер успел сменить его, старое подтверждение не принимается.

Параметры SSH и публичный ключ сохраняются в `NodeSSH` файла `/var/lib/remnamanager/panel.json`, права 0600. Отдельный `known_hosts` хранится под `/var/lib/remnamanager/ssh/` в каталоге 0700. Глобальный `known_hosts` не изменяется. OpenSSH использует `StrictHostKeyChecking=yes`, отдельный HostKeyAlias для адреса/порта и отключённое перенаправление agent и портов. Пользовательский SSH config не исполняется. Серверы без Ed25519 host key на этом этапе не поддерживаются.

Копия состояния, создаваемая пунктом «Резервная копия БД», включает SSH-настройки и публичные ключи. Сам приватный ключ в неё не включается. После восстановления настройки подключения снова проходят сверку перед открытием сессии.

На экранах выбора, ввода и подтверждения доступны Esc и F1. Запросы API и сканирование выполняются асинхронно с ограничением времени; обновление метрик не меняет выбор или содержимое формы. Отмена прекращает дальнейшее ожидание, но уже принятый сервером запрос может успеть выполниться. После отмены обновите список или статус. Поздний ответ не возвращает приложение на закрытый экран.

## Проверки

Unit-тесты проверяют массив и объект в ответе списка, точный UUID операции, повторное disable без инверсии, отказ перезапуска отключённой ноды, ответ 202 без тела, кириллицу, валидацию адресов и защиту от управляющих символов. Проверены ввод отпечатка, его смена между показом и подтверждением, сохранение pin, обязательное подтверждение операции, отмена и размеры терминала.

`TestLiveNodeManagement` проверяет список, статус, переименование, переключение состояния и запрос перезапуска Xray на настоящих backend и remnawave/node в отдельной Docker-сети. Тестовая нода подключается к панели; её порты не публикуются на хосте. Для запуска требуются свежий каталог `RM_PANEL_FIXTURE`, `RM_NODE_PROJECT` с префиксом `rmgo-nodes-test-` и `RM_PANEL_API`, совпадающий с loopback-портом этого проекта. Не направляйте opt-in тесты на рабочую панель.

Реальный OpenSSH проверяется отдельно: правильный закреплённый ключ допускает вход с временным клиентским ключом, неверный pin приводит к отказу. На Linux этот тест можно повторить в одноразовом контейнере:

```sh
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go test -c -o /tmp/remna-nodes.test ./internal/installer
docker build -t remna-node-ssh-test -f tests/docker/node-ssh.Dockerfile tests/docker
docker run --rm --network none --add-host ssh.fixture.test:127.0.0.1 \
  -e RM_SSH_INTEGRATION=1 -v /tmp/remna-nodes.test:/nodes.test:ro \
  --entrypoint /nodes.test remna-node-ssh-test \
  -test.run=TestLivePinnedSSHConnection -test.v
```

Тест создаёт собственный sshd и временные ключи только внутри контейнера, без изменения конфигурации SSH хоста. Публикация портов, привилегии NET_ADMIN и Docker socket не требуются.

API сверяется с [контроллером backend 3.4.9](https://github.com/remnawave/backend/blob/3.4.9/src/modules/nodes/nodes.controller.ts). Поведение SSH-проверки соответствует [StrictHostKeyChecking в OpenSSH](https://man.openbsd.org/ssh_config#StrictHostKeyChecking).
