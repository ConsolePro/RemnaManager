# RemnaManager v1.5.1

- Исправлена ошибка маршрутов WARP: правила 51888/51889 выполнялись после системной таблицы main (32766), поэтому трафик источника WARP и помеченный трафик выбирали eth0. Новые приоритеты — 10000/10001; номер таблицы и метка остаются 51888.
- Повторная установка автоматически заменяет старые управляемые правила, сохраняя аккаунт Cloudflare. Старый интерфейс останавливается до перезаписи его PostDown-команд. Чужие правила в используемых приоритетах не удаляются.
- До сетевой проверки проверяется фактический маршрут и для источника WARP, и для метки. Ошибка маршрута останавливает установку до изменения профиля Xray.
- Проверка Cloudflare явно использует IPv4 и обходит переменные HTTP-прокси. Если основной порт не отвечает, пробуются документированные резервные UDP-порты 500, 1701 и 4500 на том же endpoint. Успешный вариант сохраняется.
- В приватном журнале фиксируются timestamp handshake и счётчики переданных/полученных байтов без ключей. Отсутствие handshake и неправильный маршрут теперь имеют отдельные сообщения на русском.
- Регрессия воспроизведена настоящим ядром Linux в отдельном сетевом пространстве Docker: старые правила выбирают eth0, новые — rmwarp, обычный трафик сохраняет основной маршрут. Проверены миграция, резервный порт, ошибки маршрута и handshake, повторная установка и удаление.

После обновления менеджера повторите «Установить WARP Native на ноду» для той же ноды. Удалять аккаунт или предварительно удалять WARP не нужно. Проверка маршрутов не заменяет внешний WireGuard-handshake: успешное подключение Cloudflare установщик проверяет на самой ноде.
