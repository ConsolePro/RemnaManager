# RemnaManager v1.2.0

## Готовые бинарники вместо компиляции на сервере

Обычная установка скачивает готовый Linux-бинарник для amd64/arm64 из GitHub Releases, проверяет SHA256, версию и Go build identity. Go SDK и компиляция на сервере больше не требуются. Сборка из исходников остаётся только для явных `--source` и `--ref`.

```sh
curl -fsSL https://github.com/ConsolePro/RemnaManager/releases/latest/download/install.sh | sudo bash
```

Для закрепления версии:

```sh
curl -fsSL https://github.com/ConsolePro/RemnaManager/releases/download/v1.2.0/install.sh | sudo bash -s -- --version v1.2.0
```

Меню запускается командами `sudo re` или `sudo remanager`. При повторной установке сохраняются настройки и предыдущий Go-бинарник; команда `remna` остаётся для CLI панели.

## Управление и обновления

- Профиль и inbound tag создаются от имени ноды: `FN1501 → VLESS_REALITY_FN1501`. Можно переименовать профиль и добавить другие инбаунды через панель.
- Хост подписки получает флаг и название выбранной страны. Сквады настраиваются вручную, менеджер их не создаёт.
- Сохранённый SSH-ключ используется без ручного ввода отпечатка. При неудачном новом входе запрашивается пароль root для восстановления подключения и ключа.
- После изменения firewall менеджер сам проверяет отдельное новое SSH-соединение и сохраняет правила. При неудаче остаётся независимый таймер отката.
- Файлы новых нод хранятся в `/opt/remnanode`. Для установок версий 2/3 предусмотрен перенос при обслуживании.
- Добавлена смена шаблона selfsteal с проверкой HTTPS и откатом.
- Добавлено отдельное обновление Xray из официального релиза с SHA256, проверкой работающего процесса, сохранением образа ноды и откатом.
- Добавлено самообновление менеджера, выбор версии и локальный откат без изменения настроек панели и нод.

## Файлы релиза

- `remanager-linux-amd64` — готовый бинарник Linux x86-64.
- `remanager-linux-arm64` — готовый бинарник Linux arm64.
- `install.sh` — установщик готового релиза.
- `checksums.txt` — SHA256 файлов.

Поддерживаются Ubuntu 22.04/24.04 и Debian 12/13, systemd и запуск от root. Проверка нового Xray не заменяет проверку совместимости всех клиентских приложений с конкретной версией ядра.
