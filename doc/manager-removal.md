# Удаление менеджера

Откройте **«Настройки → Удалить менеджер с сервера»**. Пункт доступен при запуске установленного через `install.sh` менеджера от root в Linux. Он работает и без установленной панели, без обращения к GitHub и без Docker.

Перед подтверждением показываются точные пути удаления и сохранения. Esc отменяет операцию. Enter закрывает интерфейс, останавливает фоновые проверки менеджера и закрывает его SSH-сессии, затем выполняет очистку.

Удаляются:

- исполняемый файл `/usr/local/lib/remnamanager/remanager` и проверенные резервные версии;
- команды `re`, `remanager`, `remna_manager`, если они принадлежат этой установке;
- конфигурация и кеш в `/etc/remnamanager`, временные файлы обновления;
- журналы `install-*.log` и `management-*.log` в `/var/lib/remnamanager`.

**Панель и ноды продолжают работать.** Контейнеры, БД, подписка, Docker, Nginx/Caddy, сертификаты, задачи продления и firewall сохраняются. Удалённые `/opt/remnanode` и локальный `/opt/remnawave` не очищаются.

`/var/lib/remnamanager` с состоянием панели, журналами установок нод, резервными копиями и SSH-ключами управления сохраняется. В частности, `remnamanager-firewall.service` продолжает использовать `firewall-apply.sh` и `firewall-active.nft` из этого каталога при перезагрузке. Эти файлы нужны работающим компонентам и позволяют снова установить менеджер для их обслуживания.

Посторонняя команда `remna` панели и пользовательские файлы сохраняются. Каталоги удаляются только если опустели. Ссылки на чужие программы не удаляются; обход через symlink запрещён.

Если выполняется другая установка или обновление, очистка откажет до удаления файлов. Незавершённое обновление самого менеджера сначала нужно восстановить. Изменение приложения или конфигурации после показа плана требует открыть удаление заново.

После успешной операции менеджер печатает сообщение в обычный терминал и завершает работу. Для повторной установки используйте команду из README; сохранённое состояние компонентов остаётся на сервере.

## Проверки

Unit-тесты проверяют состав очистки, сохранение данных, отказ при изменении файлов, отмену и чужие команды. `tests/manager-remove-fixture.py` запускает настоящий установленный бинарник в PTY одноразового Linux-контейнера: отменяет удаление, проверяет отказ при занятой блокировке обновления, затем подтверждает удаление. Проверяется сохранность Compose, firewall, сертификатов, состояния нод, SSH-ключей и резервной копии. Этот сценарий включён в CI установки на Debian 12/13 и Ubuntu 22.04/24.04.
