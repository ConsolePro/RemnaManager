# Переустановка контейнера ноды

«Ноды и расширения → Управление нодой → Переустановить» пересоздаёт контейнер из закреплённого образа. Это восстановление контейнера существующей ноды, а не повторная установка всей ОС, Docker, Nginx и сертификатов.

Поддерживаются завершённые установки этой Go-версии с сохранёнными журналом и SSH-доступом. Включённая в панели нода может быть offline: операция позволяет восстановить остановленный или удалённый контейнер. Отключённую в панели ноду сначала нужно включить.

## Порядок работы

1. Выберите ноду, сверьте SHA256-отпечаток SSH-ключа и подтвердите переустановку. Перед выполнением показан сохранённый образ. OpenSSH запросит ключ или пароль, как при обновлении.
2. Мастер проверит принадлежность удалённой установки и соответствие образа в Compose журналу. Затем загрузит **тот же digest**, сохранит закрытую копию Compose и включит механизм отката.
3. Контейнер `remnanode` будет пересоздан с `--force-recreate`, даже если версия образа не изменилась. Активные клиентские соединения могут оборваться.
4. Мастер проверит запущенный Docker image ID, состояние контейнера и подключение ноды к панели, после чего завершит транзакцию.

Сохраняются точное содержимое Compose, ключ API ноды, Reality private key, short ID, UUID ноды, профиль и inbound, хост подписки и squad. Новые объекты панели не создаются. Сайт прикрытия, Nginx, сертификат и firewall не меняются. Получение `latest` не выполняется: смена версии доступна отдельно через «Обновить ноду».

## Откат и продолжение

Используется [механизм восстановления обновлений](node-update.md): независимый таймер на 300 секунд, systemd-сервис после перезагрузки и закрытый журнал транзакции. При ошибке выполняется попытка восстановить прежний Compose и пересоздать контейнер из прежнего образа. Если исходная нода уже не работала, восстановление прежней конфигурации само по себе не гарантирует исправления причины.

При потере SSH или закрытии TUI журнал сохраняется. Повторно выберите «Переустановить» либо «Обновить ноду»: незавершённая транзакция сначала будет восстановлена без запуска новой. Режим операции хранится в журнале, поэтому выбор другого пункта не превращает незавершённую переустановку в обновление. Потерянный ответ после успешного завершения распознаётся по сохранённому состоянию.

## Ограничения и проверки

Должны сохраниться `/opt/remnanode/compose.json`, маркеры владельца на ноде и `/var/lib/remnamanager/node-jobs/ID.json` на сервере панели. Если Compose удалён, восстановите его из закрытой резервной копии. Повреждённые системные пакеты, ошибочные настройки firewall, DNS или недоступность панели эта операция не исправляет. Для нод старой Bash-версии требуется отдельная миграция.

Модульные тесты проверяют пересоздание при совпадающем digest, сохранение ключей, отказ обновлять offline-ноду при разрешённой переустановке, ошибку запуска и восстановление прерванной транзакции. Тесты интерфейса проверяют выбор, сверку SSH-ключа и явное подтверждение.

Контейнерный тест Bash-агента проверяет отсутствующий контейнер, запрос сохранённого digest, обязательный `--force-recreate`, точное сохранение Compose и откат после неудачного запуска. Docker и systemd в этом тесте заменены тестовыми командами. Полная переустановка настоящей ноды с реальным systemd и перезагрузкой VPS ещё не проверена сквозным тестом.
